# OpenEMR / FHIR Integration Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A working, tested synthetic FHIR integration with SMART auth and an OpenEMR compose demo.
**Architecture:** FastAPI exposes fixed-data run/verify/delete APIs and SMART login/callback/logout. httpx handles upstream requests with explicit timeouts; no user-supplied upstream URLs or clinical data.
**Tech Stack:** Python 3.12+, FastAPI, httpx, pytest, Ruff, uv, Docker Compose.
**Spec:** `docs/superpowers/specs/2026-11-03-openemr-design.md`

## Global Constraints

Synthetic data only. Never commit secrets. Use branch skills/auto-openemr. Require green CI before authorized squash merge. Clean up owned fixtures.

## Review Focus

- Malformed/non-R4 capabilities must prevent writes.
- Unsupported updates and partial writes must be visible and safely retryable.
- Wrong references/quantities or missing synthetic tags must prevent successful verification or deletion.
- OAuth state replay, expiry, cross-browser use and token leakage must fail safely.
- TLS failures, upstream errors and pagination must not leak credentials or cross upstream origins.
